# Customs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Customs, a cost-aware scout swarm that hunts brand abuse, measures dollars per verified finding, and only ever simulates takedown submission after human approval.

**Architecture:** Pure state machines in `src/core/machines` hold every rule. Durable Actors wrap them one-to-one in `src/actors.ts`. A thin Bun server hosts the orchestrator, scouts, verifier, approvals and a WebSocket snapshot feed. Relay carries tagged messages only; state changes go through actor methods.

**Tech Stack:** Bun 1.4+, TypeScript, `durable-actors` 0.14.x, `@agent-relay/sdk` 14.x, OpenAI Decisions API (`gpt-6-luna`), Laya sidecar (Python 3.12), vanilla JS dashboard.

**Spec:** `docs/PRD.txt`

## Global Constraints

- Budget overshoot is zero: `spent + reserved <= budget` at all times, with five racing scouts.
- Case id is a hash of brand and canonical URL. Five simultaneous reports give one case and four duplicates.
- Actors never call a model. Scouts and the server call models and record results.
- Every snapshot carries a `version`; the UI ignores older versions.
- Nothing is really submitted. Results are worded as "candidates flagged for review".
- Wallet addresses and account handles are blurred on screen.
- Scam pages are never opened in the presenter's browser, and never fetched outside a sandbox.
- Orchestrator ticks about every 8 seconds; at most one steer per scout every 20 seconds; each steer has a reason.
- At most 5 questions per decider call. Laya evidence is truncated to 512 tokens.
- Thresholds are keyed by decider id and never reused across deciders.
- Live and replay run the same pipeline. Switch to tape if live returns fewer than 5 candidates in 30 seconds.
- Relay messages are `TAG {json}` with tags ASSIGN, STEER, NEW, LEAD, REVIEW, DECISION.

## PRD deviations and open questions settled from the SDK docs

| PRD said | Reality found on 2026-10-30 | Decision |
|---|---|---|
| TypeScript on Node | `durable-actors` requires Bun 1.4.2+ | Bun everywhere |
| `@Interleave` or `@Reentrant`? | `@Interleave`, and it disables rollback for the whole class | Never use it; methods stay short |
| Can actors wake on a timer? | Yes, one alarm per actor | Still unused; the design does not need it |
| Actor-to-actor calls | Not documented | Server makes every actor call |
| Laya predicate maps to yes/no choice | Laya has a native `noul` type returning a yes probability | Use `noul` |
| Decisions question limit 400 vs 10 | Docs: 1 to 400 | Still ask at most 5 |
| Decisions images base64 only? | Data URLs or public HTTP(S) URLs | Use data URLs per PRD |
| Decisions predicate returns value | Returns `probability` only; choice and score return `probabilities` and `confidence`; score is a fractional index | Normalise in the adapter |
| Laya context 512 vs 1k | Shipped limit varies by checkpoint | Truncate to 512 tokens per PRD |

No search API key exists on this machine and no Decisions access yet, so `LiveSource` and the OpenAI adapter can only be tested against stubs until keys arrive. The tape is synthetic and uses reserved `.example` domains, so no real account appears in it.

## Review Focus

1. Scout crashes between reserve and settle: the reservation must not leak forever; it expires so budget returns.
2. A budget too small for even one call: the hunt ends cleanly as `budget_exhausted` with zero spend, rather than looping.
3. Malformed Relay text (unknown tag, bad JSON, or a message from a scam page echoed in chat): parsed to `null` and ignored, never thrown.
4. Decider returns probabilities that do not sum to one, a refusal, or times out on all deciders: case is marked `undecided` for human review rather than crashing a scout.
5. Approving a case twice or rejecting an approved case: the first decision stands and labels are not double counted.
